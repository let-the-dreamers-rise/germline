Germline · open source · built on 0G

A timelock for what AI agents are told to do.

An agent that moves money is only as safe as its prompt, model and limits, and those can change overnight without a trace. Germline records every change, anchors it on 0G, and lets contracts pause the agent until the people it affects have read the change.

The problem

An agent’s prompt is its smart contract. Today anyone holding the server can rewrite it.

Agents hold money

Trading agents, agent vaults and DAO delegates act on funds other people deposited.

Behaviour lives off chain

The prompt, model, tool list and limits sit on the operator’s server. Code gets audited. Instructions don’t.

A silent rug

One line, maxTradeUsd 100 → 100000, changes what the agent will do, and leaves nothing on chain.

How it works

Record. Anchor. Enforce.

npx germline init

Record

A GitHub Action logs every change to prompts, models and agent configs (ElizaOS characters, SOUL.md, mcp.json, any config file): who made it, which pull request approved it, exactly what moved, and the eval behind it.

GermlineAnchor

Anchor

Each entry is hash-chained to the last, and the head is pinned on 0G Chain in an append-only registry with no owner. A copy goes to 0G Storage. One edited byte fails verification, offline or on chain.

GermlineGuard

Enforce

A vault calls guard.check(head) before the agent acts. Every published config change pauses the agent for a set delay, so depositors can read it and leave.

The timelock

A config change opens an exit window

DAY 0

Config A runs

Anchored and settled. The vault lets the agent trade.

DAY 3

Operator anchors B

The trade limit moves 100 → 100,000. A stops passing; B is pending. The agent is paused.

DAY 3 → 4

Anyone reads it

The diff is public and verifiable. Depositors who disagree withdraw, which is never gated.

DAY 4

B settles

After the delay the agent resumes under the new rules.

Gate any function on it:

import "germline/contracts/GermlineGuard.sol";

contract MyAgentVault is GermlineGuarded {
    function trade(bytes32 configHead, ...) external onlySettledConfig(configHead) { ... }
}

Watch the whole story run on a local chain: npm run demo:agent.

Also for teams shipping LLM features

The same record answers your auditor

SOC 2 CC8.1, enterprise security reviews and the EU AI Act (Art. 12 and 19) all ask what the model was configured to do, who changed it, and how it was tested. germline report exports an evidence pack, or one CSV row per change for Vanta, Drata or DSALTA, that the auditor re-checks without trusting you.

npx germline report --format cc81 --out cc81.csv
npx germline verify --log-id 0x… --chain --anchorer 0x… --strict

What it proves, and what it doesn’t

Proves

What the operator published, and when. Every change is fixed by a 0G block and can’t be edited, reordered or hidden afterwards. Pin the log ID and the operator’s address and even a full rewrite of the file is caught.

Doesn’t prove (yet)

That the server actually loaded the published config. A silent change now means publishing a false, permanent, attributable claim instead of an invisible edit. Binding it to execution is the 0G Compute TEE step on the roadmap.

Every attack the format catches, with the test that proves it, is listed in SECURITY.md.
