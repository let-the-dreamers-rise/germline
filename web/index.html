Change control for AI agents · built on 0G

Every change to your agent, set in amber.

An agent is only as trustworthy as what it’s told to do. Germline records every change to its prompt, model and limits, anchors it on 0G, and pauses the agent until the people it affects have read the change.

How it works

Caught, set, enforced, checked by anyone.

01 · Record

A GitHub Action catches every change

One entry per commit that touches a prompt or agent config: ElizaOS characters, SOUL.md, mcp.json or any config file. The first push backfills your history. The log lives on its own branch, so a protected main needs no bot bypass.

02 · Anchor

The head sets on 0G Chain

Entries are hash-chained, and the head is anchored in GermlineAnchor, an append-only registry with no owner, no admin and no upgrade path. A copy goes to 0G Storage, so an auditor never has to ask you for it.

03 · Enforce

The agent waits while the change cures

A vault calls guard.check(head) before the agent acts. Each published change pauses the agent for a set delay, so depositors read it and decide whether to stay. Withdrawals are never gated.

04 · Verify

Anyone can check it, without trusting you

Pin the log ID and the operator’s address, and even a full rewrite of the file fails. Run germline verify, or drop the log into the browser verifier. It uploads nothing.

What’s inside

Built so the record holds up.

Hash chain

Each entry carries the hash of the one before it. One edited byte fails verify, offline.

Ownerless registry

No owner, no admin, no upgrade path. Every anchor ever made stays readable.

Copy on 0G Storage

The log’s root goes on chain, so an auditor can fetch it without asking you.

0G Compute review

A model writes a two-sentence summary and a risk level. It’s advice, never an approval.

Straight answers

What it is, and what it isn’t.

Does Germline make us compliant?

No. It produces evidence for one control, change management of AI behaviour. Your assessor decides the rest. The evidence pack maps the record to SOC 2 CC8.1, EU AI Act Art. 12 and 19 and ISO/IEC 42001, and says “Not yet” wherever the log can’t back a claim.

Does it prove the server ran the published config?

Not yet. It binds what the operator publishes. A silent change now means publishing a false, permanent, attributable claim instead of an invisible edit. Binding it to execution is the 0G Compute TEE step on the roadmap.

Does it log what the model said?

No. LangSmith and Langfuse record inference traffic. Germline records what the model was configured to do, and makes that record impossible to quietly rewrite.

Does it authenticate commit authors?

No. Git lets anyone write any name. The approval comes from GitHub’s API and is authenticated; the author line is only what git says. Signed entries are on the roadmap.

What do I need to start?

Run init in the repository that holds your prompts and config, then commit and push. To anchor on 0G, add a funded 0G key as the secret GERMLINE_ANCHOR_KEY. Until then the log is still recorded and verified on every push.

Does it run on BOT Chain?

Yes. The anchor-only flow needs only an EVM RPC and a funded key, with no 0G Storage or Compute. GermlineAnchor is live on BOT Chain mainnet at 0xA0448Cd6…7b25. Anchor from your own wallet in the anchor app, or from the CLI with GERMLINE_NETWORK=botchain, and check any anchor on scan.botchain.ai or in the verifier.

Is it live on 0G mainnet?

Not yet. The anchor registry and the guard are tested on a local chain. Mainnet deployment needs a funded key, and npm run deploy:anchor does it.
